# openwebui-chat

A command-line tool that lets AI agents (Hermes, Codex, etc.) chat with models hosted on **Open WebUI**, creating persistent, web-visible chat records that preserve the native Open WebUI experience.

## Why?

When an agent uses `openwebui-chat`, the conversation is stored as a native Open WebUI chat. This means:

- **Persistent web-visible records** — every conversation appears at `/c/<chat_id>` in Open WebUI
- **Auto-generated titles** — Open WebUI automatically names each chat session
- **Human-readable history** — read back full conversations through the normal UI
- **No duplicate transcript stores** — Open WebUI is the single source of truth

## Quick start

```bash
# Set up your environment
export OPENWEBUI_BASE_URL=http://your-openwebui:8080
export OPENWEBUI_API_KEY=sk-your-key
export OPENWEBUI_DEFAULT_MODEL=your-model-name

# Start a new chat — returns immediately after submission
openwebui-chat start \
  --title "Hermes to local model" \
  --message "Respond with a short confirmation."

# Wait for the assistant to finish
openwebui-chat wait \
  --chat-id "$CHAT_ID" \
  --message-id "$ASSISTANT_MSG_ID"

# Send a follow-up message in the same chat
openwebui-chat send \
  --chat-id "$CHAT_ID" \
  --message "Now provide a second response."
```

## Commands

### `start` — Start a new chat

Submits the first user message, creates a persistent chat, and returns immediately.

```bash
openwebui-chat start [OPTIONS] --message <MESSAGE>
```

| Option | Default | Description |
|--------|---------|-------------|
| `--message` | *(required)* | The user message to send |
| `--model` | `$OPENWEBUI_DEFAULT_MODEL` | Model to use |
| `--title` | *(auto-generated by Open WebUI)* | Chat title hint |

Output (JSON):
```json
{
  "chat_id": "abc123...",
  "assistant_message_id": "def456...",
  "user_message_id": "ghi789..."
}
```

### `send` — Send a follow-up message

Appends a message to an existing chat.

```bash
openwebui-chat send --chat-id <ID> --message <MESSAGE> [OPTIONS]
```

Output: same JSON format as `start`.

### `wait` — Wait for a response

Blocks until the assistant's response is complete, then prints the full message content.

```bash
openwebui-chat wait --chat-id <ID> --message-id <ID> [OPTIONS]
```

| Option | Default | Description |
|--------|---------|-------------|
| `--timeout` | `3300` | Maximum wait in seconds |
| `--poll-interval` | `3` | Polling interval in seconds |

Output (JSON):
```json
{
  "status": "completed",
  "content": "The assistant's full response text...",
  "chat_id": "abc123...",
  "message_id": "def456..."
}
```

On timeout:
```json
{
  "status": "pending",
  "chat_id": "abc123...",
  "message_id": "def456...",
  "content": ""
}
```

### `doctor` — Diagnose connectivity

Checks your Open WebUI connection, API key validity, and prints required endpoints.

```bash
openwebui-chat doctor
```

### `models` — List available models

```bash
openwebui-chat models
```

## Configuration

Configuration is resolved in priority order (highest first):

1. **CLI flags** (`--model`, `--timeout`, etc.)
2. **Environment variables** (`OPENWEBUI_*`)
3. **TOML config file** (`~/.config/openwebui-chat/config.toml` or `./openwebui-chat.toml`)
4. **Built-in defaults**

### TOML config example

```toml
# ~/.config/openwebui-chat/config.toml
base_url = "http://localhost:8080"
api_key = "sk-your-key"
default_model = "llama3"
timeout = 3300
```
